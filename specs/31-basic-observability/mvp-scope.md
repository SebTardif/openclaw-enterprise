# Basic observability: MVP scope and dependencies

**Status:** Selected proposal; implementation and qualification pending.

Use this checklist to split the [Basic Agent observability RFC](../31-basic-observability.md) into reviewable changes. The linked contracts own behavior and unresolved decisions; a completed source slice proves only its stated boundary.

## Required outcomes

The selected MVP supports personal and team Agents through the existing resource model. Full MVP acceptance requires three distinct people: deployer A, requester B and separately granted audit reader C.

1. **Current audit access.** Every exact-Agent History request requires current selected-IAM `read_audit`, including subsequent pages. Exercise personal/team grants, cross-Agent/Namespace denial, revocation, account and group changes, and restrictions. Ownership, membership, participation and deployment permission confer no access.
2. **Explicit administration.** Installation administrators grant/revoke `audit_reader` and `audit_retention_administrator` through the common IAM administrative route, atomically with evidence. Retention administration grants no History access. See [access and disclosure](interfaces.md#authorization-and-policy-consumption).
3. **Truthful lifecycle.** Create, update, deploy, stop, retries, supersession, completion and failure preserve authentic causation. Requested, accepted, observed and unknown remain distinct; queue completion cannot prove workload stop or provider success.
4. **Safe facts.** Persist and disclose only the [closed, bounded projection](interfaces.md#facts-and-events). Reject unsupported versions/fields, excessive depth/size and unsafe values. Exclude raw details, transcripts, credentials, commands, URLs, headers and provider bodies; prove secret exclusion at both boundaries.
5. **Atomic evidence and exact recovery.** Privileged local mutation, work intent and mandatory evidence share original State. Rollback removes all; uncertain COMMIT stays unknown. [Exact mutation recovery](interfaces.md#mutation-outcomes) reauthorizes the original action, observes only the bound result and creates no work. Protected disclosure requires acknowledged evidence COMMIT.
6. **Bounded query.** Use indexed exact-Agent queries, at most 100 events, closed filters and authenticated subject-bound cursors with fresh authorization. Expose no total count or unbounded Installation scan.
7. **Small console.** The real History route supports loading, empty, denied, error, pagination, stale-response and unknown-outcome states. An audit-only reader reaches retained History without configuration-read permission.
8. **Retained Agent authority.** Deletion preserves authentic historical parentage and exact retained-Agent grant/revoke/regrant. Current IAM still decides access; a live Agent lookup is not an authorization prerequisite.
9. **One authentic repository read.** B initiates one approved read-only GitHub HEAD operation through an actual ordinary-Agent/Harness turn and managed Git child. C sees B separately from A and the Agent/revision executor, exact resource/authorization, accepted operation and strongest observed or unknown result. Follow [repository-read acceptance](repository-read.md#acceptance-and-delivery); model text, copied headers and controller Git cannot supply initiation proof.
10. **Retention and restore.** Default expiry is 30 days from trusted receipt, with physical live-ledger erasure within another 24 hours; an authorized Installation setting may explicitly select indefinite. Qualify both modes, legacy rows, transitions, races, restricted purge, restart and [restore continuity](retention.md#restore-and-copy-ownership). Expired evidence never resurrects; live deletion makes no independent-backup erasure claim.
11. **Safe operational health.** Append refusal, unknown COMMIT, storage pressure and overdue erasure appear in sanitized health without protected content or high-cardinality labels. Preserve the [evidence-failure rules](security.md#audit-failure-and-protective-work).
12. **Connected acceptance.** Review the integrated shipping tree, including SQL and security. Each cumulative RFC-first cut must build and pass its applicable checks; the final stack tree must equal the accepted feature tree. Record source/database, composed, installed, live-provider and release proof separately, including missing evidence.

## Dependency cut points

**Independent diagnostics** use existing filtered logs and optional local files. Their [own acceptance](architecture.md#availability-and-delivery) preserves current authentication, authorization and mandatory audit. They establish no protected History or repository-read qualification.

**Non-serving source slices** can define and validate contracts before all suppliers join. They must leave protected History unavailable. Source acceptance neither enables disclosure nor completes an adjacent capability.

**First serving lifecycle History** integrates current local account/method/session guards, selected IAM and original State with lifecycle producers, API and console. It also requires the complete retention/restore contract and exact recovery, including restart, replicas and key rotation. These are prerequisites to disclosure. Local accounts suffice; federation and Google/GitHub login are not prerequisites.

Use original State transactions/recovery, `PlatformUnitOfWork.audit.queryAgentHistory` and its lifetime binder, and raw-SQL migration integration. IAM supplies `IAMPolicyAdministrationV1.bindPolicy`; OCC owns `readPolicy/applyChange/readPolicyOperation`. Require read-bound authorization and currentness guards. Accept and compile these exports and review participating writers; completion of whole RBAC or OIDC programs is unnecessary. Unsupported suppliers keep History unavailable.

**The full selected MVP** also integrates accepted `AgentInvocation`, `AgentAuthorityContext` and `AgentInvocationRuntime` exports with the credential owner's real session/exchange and safe observation exports. Qualify one actual execution profile under [authentic handoffs](repository-read.md#connect-authentic-handoffs) and [currentness and closure](repository-read.md#currentness-and-closure). SPIRE, gVisor and egress program completion are not blanket gates; any receiving, isolation or transport control required by that profile remains an explicit dependency.

## Decisions still required

Owners must settle [producer/event membership](interfaces.md#facts-and-events), [expiry crossing at release](retention.md#expiry-and-concurrency), [recovery-reference validity and key continuity](interfaces.md#mutation-outcomes), [guarded purge authority](retention.md#database-and-runtime-enforcement), and [restore authority and custody](retention.md#restore-and-copy-ownership) before accepting dependent implementations. This checklist chooses no new values or protocols.

No new journal, generic registry, broad search, transcript store, arbitrary retention periods, legal holds, remote export or independent witnessing is included. Existing owners retain enforcement and credential custody. Proposed scope and completed source checks remain distinct from shipping acceptance.
