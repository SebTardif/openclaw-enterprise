# Selected native ROOT IAM admission

`createNativeRootIamAdmissionV1` constructs the OpenClaw Control Plane (OCC)
selected-IAM effect participant from trusted startup dependencies. It prepares
one-use evidence for credential operations, resource dispatch, PR creation and
authenticated ROOT cancellation. Production broker, Work and State composition
remains pending; the component does not issue dispatch permits.

## Admission

External effects require the actual service principal to operate the exact owning
Agent and every independently registered protected Secret. Explicitly registered
source-free bridges require zero protected sources; missing sources cannot select
that mode. The component runs the real native evaluator against full policy
arrays and also requires an independently retained exact service entitlement,
immutable ROOT ceiling, current policy, grant, profile, recipe, audience, data
domains and named capacity charges. Requester privileges cannot replace the
Agent's service permissions.

Trusted composition must supply the required internal `grantOperations` owner.
It receives only a detached, frozen original grant read by State and projects
synchronous registered-operation DATA. The component checks complete grant,
connection generation, definition, retained operations and fixed profile
correspondence. One whole tuple must match service, exact business action,
canonical resource and profile-selection digest; fields from different tuples
cannot combine into a permission. Schema validity and service possession alone
cannot authorize a backend operation.

Projection runs during preparation and again after the original consume fence
and effect read. The full checked projection participates in the retained facts
comparison. Core, original request bounds, abort and every applicable deadline
are rechecked after projection and every wait. Output must be inert finite JSON
within 64 KiB and depth 32, with 1–256 complete tuples. `canonicalResource` is
a nonempty string of at most 4096 UTF-8 bytes and UTF-16 code units; the other
tuple strings retain their 256-byte and 256-code-unit limits. Missing, asynchronous, malformed, hostile or refused
projection denies; no default or predicate fallback exists.

The original Work recognizer authenticates Core custody and returns the complete
immutable identity and policy. The original effect owner supplies the request's
abort signal and deadline and reads retained effects independently during both
preparation and consumption. Every binding field must agree, including current
recipe/interpreter identity and the original opaque PR claim. Copying or encoding
DATA cannot recreate original Core, PR or IAM evidence.

Cancellation uses the independently authenticated canceller and current exact
cancellation authorization, ROOT and dependencies, plus native operate on the
owning Agent. Business `work.cancel` never enters native IAM's action vocabulary.
Withdrawal of external service entitlement leaves this separate cancellation lane
available while its own authorization remains valid. Initial Controller deployment
is a separate six-operand policy-owner contract with no Core; this component does
not implement that lane.

## Bounds and transaction outcome

Preparation runs outside the broker admission transaction under State's preparation
fence. Original request, caller deadline, authority, finite ROOT, entitlement and
configured bounds intersect. Caller deadlines only shorten. Evidence has a finite
lifetime and bounded active registry; expiry cleanup is lazy and has no persistent
timer. Temporary wait timers and abort listeners are removed when each wait ends.
An identical-version gateway restart loses local evidence permanently.

`consumeIn` enters State's whole-callback participant before checking evidence,
Core or bounds. State must synchronously enroll and invoke it. The callback spends
evidence synchronously before its first await, acquires the policy/selection fence,
reads originals in the same authentic unit of work, and rechecks expiry, abort and
currentness after waits. Every failure must poison outer COMMIT even if caught or
unawaited. Rollback and unknown COMMIT never restore spent evidence.

IAM returns `void`. The regular credential broker must join genuine Work checks
and original grant/profile/lease/capacity/reservation/claim transitions in that same
unit. Only a known successful outer COMMIT may release a dispatch permit.

## Availability and verification

This source supports one active gateway, one immutable service-owned ROOT per
execution and one immutable admitted bundle version with identical-version restart.
Listing, pagination, remote broker execution, replicas and concurrent versions are
deferred. Unsupported driver or selection modes deny; ordinary authorize plus TTL
is not a fallback.

The original State owner must extend the same runtime authority guard with
nonserial participant enrollment, sticky failure and drain while preserving serial
mutations. Serial nesting around an awaited owner read deadlocks. Genuine all-writer
policy fencing, SQL behavior, application-role enforcement and real broker/Work/State
integration are pending. Component checks use named controlled peers only at these
absent owner boundaries; see [CI proof limits](../testing/ci.md).

The test-only `OriginalRegisteredGrantProjectionPeer` uses the actual admitted
JSON operation and profile codecs, restores and retains each original value,
and parses canonical JSON as unknown under its fixed fixture semantics. Its
`github.read` and `github:repo` labels exercise all external effect families,
including PR creation, solely as controlled correspondence values. The original
production owner must supply the actual provider-specific registration and operation
mapping before provider composition; this peer establishes no production PR
permission or live-provider qualification. Projection types remain internal.

A denial requires fresh original evidence and current authorized facts. Never retry
an uncertain commit by recreating a handle. These checks do not establish installed
Kubernetes/gVisor, live GitHub execution or release readiness.

## Canonical resource bounds

Original projected tuples require a nonempty string `canonicalResource` of at
most 4096 UTF-8 bytes and 4096 UTF-16 code units. `serviceId`, `exactAction` and
`profileSelectionDigest` retain their 256-byte and 256-code-unit limits. Exact
resource equality, the 256-tuple cap and the 65536-byte canonical snapshot with
depth 32 and its existing node cap remain enforced. Individually valid tuples
can still exceed that aggregate envelope. Resource encoding retains complete
opaque IDs; see [resource correspondence](backend-recipe-operations.md#resource-correspondence).
