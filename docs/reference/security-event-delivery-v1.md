# Protected security-event delivery primitives

The security-event delivery leaves provide a bounded append/readback codec, a local submission adapter and a PostgreSQL repository factory. They consume the existing [security-event contract](security-events.md). They are source primitives awaiting the original transaction/outbox, producer and access composition. They are not installed by production startup, exported as a remote service or connected to an exporter. The existing legacy `AuditEvent` ports and [operational diagnostics](operational-diagnostics.md) remain unchanged.

The canonical event contains approved opaque UUIDs. The delivery predicates preserve the existing canonical reference domain, including UUID versions one through eight; they do not replace valid retained identities. Existing OCC Installation, Namespace and audit row IDs can use different identifiers. The storage factory therefore retains both the actual raw outbox ownership tuple and the canonical event scope. Its constructor takes a server-owned `securityScope` mapping alongside the existing guarded `RepositoryScope`, snapshots both, and preserves them throughout the transaction. A structurally valid mapping is not proof of authenticated producer custody. The original producer/projection owner must supply that mapping; the adapter never invents one from labels, hashes or a legacy audit row.

## Callable source boundaries

`security-event-delivery-codec-v1.ts` owns the closed append and result formats. An append carries version one, the canonical Installation/event key, producer instance/positive sequence, obligation reference, canonical event UTF-8 and a SHA-256 equality digest. The decoder rejects duplicate decoded member names, unknown members, unsupported versions, oversized/deep input, noncanonical event bytes and conflicting event identity or digest. A digest establishes equality, not authentication. Invalid input produces a constant error without the input or its cause.

`createSecurityEventDeliveryV1` consumes an original-owner transaction boundary. Its `transact` promise must settle successfully only after the outer transaction acknowledges COMMIT. A nested repository result is `Staged`; it cannot be used directly as a committed receipt. The adapter validates and binds the owner result to the original event key/digest. Generic rejection, cancellation, timeout, malformed response or a foreign receipt produces an unknown result and preserves the obligation. Its `read` boundary must perform a fresh authorized exact read after the preceding unit has unwound.

`createPostgresSecurityEventDeliveryV1` is an internal repository factory using the original guarded query and lifetime. It cannot acquire a connection, open or finish a transaction. `stage` requires a writable READ COMMITTED unit, resolves and locks the actual selected `audit_export_outbox` row, and verifies raw Installation, Namespace, audit event ID, original operation and the existing `lifecycle-protective-v1` origin. That current supported origin is not generalized to arbitrary component events. A supplied pending object is not accepted as proof that an obligation exists.

The original single outbox remains the obligation owner. The new record retains its audit row reference, full raw ownership correspondence, canonical event key and scope, canonical bytes/digest, producer instance/sequence, obligation, original receipt time, immutable receipt reference and charged size. Event, sequence, obligation, outbox and receipt uniqueness prevent replacement. The current outbox has only a single-column audit ID key; the table factory references that actual key and the adapter resolves the remaining owner fields on the same guarded client. It does not assume a nonexistent composite foreign key.

The constructor's read method requires a read-only unit and exact retained correspondence. It returns `Committed`, `Conflict` or `Unknown`. **It never emits `AbsentFenced`: an empty query cannot prove that an earlier append will not commit.** The wire format can represent `AbsentFenced` for a future backend that actually supplies authoritative fencing. Expired events are refused for staging and not returned as current readback proof. Age uses a fresh database clock sampled after the relevant locks and exact lookup, preserving PostgreSQL timestamp milliseconds; unusable clock results fail closed. This check does not implement physical erasure.

## Commit and recovery behavior

| Result                      | Meaning and responsibility                                                                                                                                                                                      |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Staged`                    | Internal provisional repository result. The original owning transaction still controls commit or rollback.                                                                                                      |
| `Committed`                 | The owner has completed the actual durable boundary and the receipt binds the exact event and digest. The producer must durably record transfer; loss of that acknowledgment requires identical reconciliation. |
| `RefusedBeforeCommit`       | Definitive refusal of this append before acceptance. It cannot erase a separate earlier uncertain attempt or its obligation.                                                                                    |
| `CommitUnknown` / `Unknown` | Keep the immutable obligation and exact original IDs. A deadline or disconnected caller is not evidence that server work stopped.                                                                               |
| `Conflict`                  | Identity, producer sequence, obligation, origin or immutable content was reused inconsistently. Preserve evidence for repair; do not overwrite or retry under a new ID.                                         |
| `AbsentFenced`              | Only a backend with proof that every prior append finished, aborted or was fenced may produce it. Not implemented by this PostgreSQL leaf.                                                                      |

`securityEventRecoveryDecisionV1` consumes persisted round state and an already verified exact readback. It requests exact readback while an earlier attempt is uncertain, permits an identical reserved attempt only after a genuine fenced-absence result, and retains unresolved obligations for repair after five rounds. It schedules nothing and persists no attempt itself. Production must reserve attempts durably before dispatch, retain original bytes/sequence/times on restart, and authenticate exact recovery separately from retired producer origination. No delivery receipt grants runtime authority, completes stop or credential revocation, releases a lifecycle operation or proves an external effect.

The mandatory operation/intent and security-event obligation must share the original owning transaction. An original-owner awaited stage callback belongs after its existing outbox insertion and before the unit seals; any required staging refusal or failure must abort/poison the complete unit. The original private callback must inspect the returned union and throw on `RefusedBeforeCommit`; merely awaiting the result is insufficient. It must bind the actual validated and locked Namespace inside the admitted operation, using the original guarded lifecycle query. That callback, its authentic event selection and post-COMMIT composition are not supplied by these leaves. Remote export failure must not block protective work already durably accepted under its original contract, and failure of local mandatory persistence cannot be called accepted intent.

## Capacity and diagnostics

The codec bounds the complete request to 16 KiB and response to 1 KiB; the canonical event remains limited to 8,192 bytes and depth six. The local adapter permits at most 64 active operations, eight for one server-selected Agent or authorized non-Agent service, and 1 MiB of encoded request payload, with no waiting queue. Repeated concurrent use of the same event stays unknown. On timeout/cancellation the adapter retains an occupied slot until its owner promise settles, so abandoned work cannot silently free capacity for unlimited replacements. Health uses fixed count labels and exposes saturation without raw errors or event bodies.

These in-flight counters bound **one local adapter instance**. Production must select one shared admission owner across all participating producers/processes before claiming the global limits; multiplying instances does not multiply the promised budget. The owner must also bound underlying query cancellation/join or retain durable recovery ownership. A two-second caller deadline is neither a hard stop of PostgreSQL work nor a measured latency guarantee.

The PostgreSQL factory locks one Installation capacity row and atomically reserves a pending event, its serialized envelope bytes and a retained-byte charge before inserting the event. Identical duplicates reuse their first receipt without another charge. The schema limits configured pending capacity to at most 10,000 events and 64 MiB, including uncommitted reservations. Configuration requires an explicit retained-store ceiling and per-record overhead; the source invents no deployment quota. The original owner must account for existing obligations, producer/sink/export copies and all participating producers when provisioning that shared row. A freshly zeroed counter is not evidence that existing obligations disappeared.

The table factory defines new records and capacity only. Original schema composition, application grants and immutable-record enforcement, capacity provisioning, outbox claim/acknowledgment state, export and retention sweep remain required. There is no release/decrement API that could silently remove an accepted obligation. Export retains its separate 100-event/five-attempt policy. Thirty-day retention begins at immutable trusted receipt and requires erasure within the additional 24-hour sweep; current age checks are not that erasure implementation. Retained-store overhead, exported copies, sweep throughput, filesystem reserve and actual memory remain unmeasured. Accepted records must not be evicted to conceal saturation.

## Verification and current limits

Run the focused source controls with an already prepared matching Node workspace:

```sh
node --test tests/conformance/security-event-delivery-v1.test.mjs
```

These cases exercise the actual codec and local adapter: immutable/digest correspondence, hostile/duplicate/bounded JSON, closed outcomes, delayed owner completion, cancellation/deadline uncertainty, occupied capacity, wrong receipts and finite recovery decisions. Their transaction boundaries are controlled inputs. They do not establish PostgreSQL persistence, authentication, global admission or exporter behavior. The strict consumer fixture composes the actual new wire/storage types and rejects a provisional receipt where a committed one is required.

The callable API consumer covers the codec, local adapter, OCC port and PostgreSQL query adapter. The separate complete schema-factory consumer did not pass strong compilation with the currently prepared Drizzle declarations: a first run exhausted its heap and a larger run reported installed declaration errors alongside a subsequently corrected local narrowing error. The schema-factory branch remains unqualified by a successful strict compiler run; no relaxed declaration checking or replacement declarations are used as proof.

The PostgreSQL test source uses a separately selected migrated lifecycle-admission database, restricted application identity, original lifecycle fixture producers and genuine existing outbox rows. It performs no DDL. Selecting `OCC_SECURITY_EVENT_DELIVERY_POSTGRES=1` additionally requires the existing dedicated lifecycle database settings and original-owner preparation of the new tables and roles. Its authored cases cover rollback, blocked first-insert and sequence contenders, committed and rolled-back capacity reservations, pending/retained byte exhaustion, expiry during an observed lock wait, changed binding, read-only and closed-unit checks, and deliberate loss of a caller result after real COMMIT. These are executable database test bodies awaiting the separately selected database, not executed results. The storage fixture's capacity values and canonical scope mapping are synthetic and are not a production configuration or authenticated grant. It does not exercise the missing production mandatory-event callback or a process/power-loss fault.

The database suite has not been executed for this source increment. Production callback/outbox composition, authenticated write/recovery and scoped reader/retention roles, actual emitters, restart/crash behavior, global capacity, exporter and physical erasure remain explicitly unqualified. These leaves neither invoke a provider nor enable a protected writer by themselves.
